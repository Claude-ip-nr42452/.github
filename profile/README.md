<p>「按流量计费到底省不省」这个问题，靠推算很难有结论，因为用量曲线、任务重试、闲时停机三件事互相影响。比较靠谱的办法是做一次小规模对照实验：三组同样的任务、同样的账号规模，分别用按流量、包月、按端口跑两周，把账单和失败率放在一起看。这篇给出实验的设计、变量控制办法、一组示例数据，以及怎么读结果才不会得出相反结论。</p>

<h2>一、实验怎么设计：三组并行，任务完全相同</h2>
<p>目标不是证明哪种便宜，而是找出「在你的用量形状下，哪种更省」。所以三组必须同源，否则比出来的差异没有意义。</p>
<h3>分组与周期</h3>
<p>三组各五个账号，账号年龄、所在地区、日常任务量尽量拉齐。跑满 14 天，其中包含两个完整周末，因为周末的用量往往和平时差很多，只跑工作日会失真。</p>
<h3>记录哪些字段</h3>
<p>每天记四项：实际流量（上行与下行分开）、会话数、失败请求数、账单金额。四项缺一项，结论就会含糊——只看账单不知道是任务少了还是单价低了，只看失败率又不知道代价。</p>

<h2>二、变量控制：只改计费方式</h2>
<p>对照实验最大的敌人是「顺手改了别的」。下面几条是必须锁死的。</p>
<h3>锁死出口地区与运营商</h3>
<p>三组都用原生家宽、同一城市、同一运营商的不同段。如果一组的出口在另一个国家，延迟和验证率都会不同，账单比较就失去意义。</p>
<h3>锁死脚本与时段</h3>
<p>同一套脚本、同样的请求间隔、同样的运行时段。A 组跑白天、B 组跑夜里，流量必然不同。这一点看似常识，实际做的时候最容易忽略。</p>
<h3>允许的唯一差异：停机策略</h3>
<p>按流量组允许在低峰期完全停用，这也是它的核心卖点。其他两组保持常开。这条差异要在记录里单独标注，否则读数据时会把「停机省下的」和「单价低省下的」混在一起。</p>

<h2>四、结论怎么读：三种形态各自胜出的区间</h2>
<p>数据摆出来之后，容易得出「按流量最便宜」的结论，这个结论只在特定条件下成立。</p>
<h3>按流量胜出的条件</h3>
<p>用量低且波动大、可接受停机、重试率低。三者缺一，优势就会被吃掉。上面这组数据里，如果把重试率从 11% 压到 3%，按流量组能再省 8% 左右；反过来，如果任务失败率升到 5%，重试流量会把省下的钱全吃掉。</p>
<h3>包月与按端口胜出的条件</h3>
<p>用量平稳、不能停机、账号价值高。包月最贵但最省心，适合主号；按端口居中，适合需要固定通道但用量不极端的场景。两者在实验里的失败率都低于按流量组，差距不大但方向一致。</p>
<h3>把结论落成一张映射表</h3>
<p>不要记住「哪种便宜」，记住「什么形状配什么形态」，下次用量变了直接查表。</p>

<h2>五、淡季停机这一条要单独验证</h2>
<p>「淡季能停掉」是宣传里最容易被夸大的功能，实际能不能停、停了会不会丢配置，要自己试一次。</p>
<h3>停机后配置是否保留</h3>
<p>有的方案停用后地址释放，重新开通时分配新地址，等于一次跳变，老号要重新适应。有的保留地址只停计费，差别很大。做一次「停三天再开」的测试，记录地址是否变化。</p>
<p>另一个要问清的细节是最小停机单位：按天、按周还是按月。如果最小单位是一个月，淡季停用的意义就打折，这一条同样要实测，别只看宣传文案。</p>
<h3>重启后的观察期</h3>
<p>长时间停用后重新上线的账号，前几天要放慢节奏。建议重启后头三天只做日常操作，不要直接跑批量，观察验证次数是否上升再决定是否加量。</p>

<h2>常见问答</h2>
<h3>实验只跑两周，结论可靠吗？</h3>
<p>答：对「哪种形态更适合当前用量」这个问题，两周足够看出方向；对单价与长期稳定性，两周不够。建议两周定形态，再用一个月验证稳定性。</p>
<h3>按流量的重试流量能压下来吗？</h3>
<p>答：能压一部分。把超时设合理、失败后退避重试、避免同一请求连续重发，通常能把重试占比从一成降到三四个百分点。这部分收益在按流量方案里是直接的钱。</p>
<h3>三组账号不一样多会影响结论吗？</h3>
<p>答：会。必须按单账号日均成本比较，不能直接比总账单。若账号数无法拉齐，用平均值而不是总额，并且把账号年龄差异记录下来。</p>
<h3>淡季停用会不会影响账号状态？</h3>
<p>答：可能有影响。长期不登录本身是一个信号，重新上线时环境若有变化，验证概率会上升。停用前把环境与配置完整备份，重启时按原样恢复。</p>
